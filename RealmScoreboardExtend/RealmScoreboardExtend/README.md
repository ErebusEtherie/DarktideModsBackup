## 0.2.3 玩家漏列与历史列表刷新

- 修复同名机器人或玩家标识暂未加载时，名单记录被覆盖／漏掉的问题。需要区分时使用本局的联机槽位建立独立记录，包含 Realms 的 `local_player_id=0`；正常且唯一的原始统计键继续保留。名字稍后加载完成时接回已有记录，LoadoutMonitor 装备快照使用同一套记录标识。不会更改游戏玩家的账号、名字或联机标识。

统计边界：若上游 scoreboard／插件已将两个同名机器人的数据写进同一统计键，这些合计数字无法可靠拆分。本版保留两列及独立装备，但不会复制合计数字伪装成另一人的数据；没有独立统计的单元格遵循基础计分板的零值规则。旧历史若当时只保存了 7 名玩家，也无法补出从未保存的第 8 人。

- 原始统计键、旧 `[BOT]`／`[DC]` 历史标记与完整装备快照继续保留；翻译仅影响显示。历史中的插件文字保留保存时的语言，本 Mod 生成的界面提示与装备行标题使用当前界面语言。
- 单独更新使用 `RealmScoreboardExtend-0.2.2-test.zip`；包含原有玩法协调的完整包为 `RealmScoreboardExtend-0.2.2-test-9.11-Compat.zip`。本次未改动其他 Mod 的玩法或网络同步逻辑。

本地检查：336 个 Lua/Mod 文件语法通过；真实 DMF 的中英文及回退、所有格式参数、多语言文字在三种视图中的传递、UTF-8 截断、历史往返和旧记录兼容通过。原八人、分页、返回、装备和合集逻辑回归通过。未在游戏内验证字形、实际排版或输入法；本版接收游戏及插件提供的字符串，不新增文本编辑框。

建议实测：分别使用简体中文和英文启动游戏，检查模组选项与 `/rse_status`；让混合语言姓名及含 `%` 的插件文字出现在计分板，再打开新保存的历史核对。过长文字仍会缩小或省略显示，保存内容保持完整；字形覆盖由游戏字体决定。

## 保留 0.1.2 的修复

0.1.2 修复结算背景、历史返回和历史颜色。保留 0.1.1 已经实测正常的对局内计分板、完整名单、三种视图的分页逻辑和按键设置。

- **结算背景**：0.1.1 的视图更新包装只返回了原函数的第一个返回值，丢失第二个“继续绘制底层视图”的标记。游戏据此停止绘制底层视图及其关联世界。现在保留输入和绘制两个返回值，使八人面板下的结算场景、原继续/离开流程能够正常工作；不修改结算世界资源或 Realms 联机逻辑。
- **历史返回**：点击历史条目打开居中的独立详情页，底部显示 Esc／返回提示。按一次 Esc 只关闭详情，回到原来的列表、选中记录和滚动位置；在列表再按 Esc 才退出历史。详情期间阻止输入传到列表；列表焦点变化不再自动打开详情，避免返回后立即重开。旧四人记录和新八人记录使用同一流程。
- **历史颜色**：按完整历史名单和原 scoreboard 的 ASC／DESC 判断恢复最佳、最差、零值颜色及本机标签颜色；遵循原 scoreboard 的颜色设置。跨页比较，不把本页最高误当成整局最高。插件自带文本格式保留；不重新归一化、汇总或改写历史文件里的统计数字。

更新时退出游戏，安装 RealmScoreboardExtend 文件夹，并从加载列表移除旧 ScoreboardRoster；仍需停用 RealmsScoreboard8。无需删除历史或重置设置。每页人数沿用现有设置；如果上一轮测试改为 4，请手动改回 8。

## 安装测试

1. 退出游戏。把压缩包中的 `RealmScoreboardExtend` 文件夹复制到游戏的 `mods` 目录。
2. 在 `mod_load_order.txt` 中用 `RealmScoreboardExtend` 替换旧 `ScoreboardRoster`，放在 `scoreboard`、`LoadoutMonitor` 以及额外计分板插件之后。首次安装则添加新名称。
3. **确认旧 `ScoreboardRoster` 和 `RealmsScoreboard8` 均不加载，再启动游戏。** 同时启用时，新扩展会提示并停止安装自己的钩子，避免争用界面。
4. 游戏内模组选项中找到“RealmScoreboardExtend”，确认对局、结算、历史每页人数均为 8。
5. 原 scoreboard 的战术计分板和保存历史选项仍由原 Mod 控制。

推荐加载顺序（原有依赖保持原顺序）：

## 第一版功能

- 对局中、结算、历史视图自动生成玩家列，每页人数分别可设为 1–12，默认 8。
- 超出人数通过 **Page Up / Page Down** 翻页；按键可在模组选项重新绑定。页码与当前按键显示在左上统计名称列。
- 当前真人优先，然后离线真人，最后机器人。显示标记随界面语言变化，历史内部仍使用 `[DC]`／`[BOT]`。按同一优先级保持本局首次观察的顺序；历史同类玩家按账号标识稳定排序。
- 同一局内保存已观察到的玩家名字与职业。同一账号的队友重新加入后接回已有记录，不另建一列。
- 页面上限不限制历史保存人数；新历史继续使用 scoreboard 原格式，可由其原读取器读取。旧历史中未保存的玩家姓名无法凭空恢复。
- 以实际渲染器的 UI 比例、分辨率、宽高比计算可用宽度。历史详情使用独立居中面板，通过 Esc 返回列表。字体到最小值后用省略号处理过长内容，另有宽度与字体百分比设置。
- 复用通用统计行接口，保留子行、汇总、图标、颜色及文本值。使用渲染数据副本，避免分页计算改变原始统计。
- 数据采集保持本机 scoreboard/插件的机制，不新增网络统计同步。

## 兼容范围与边界

源码检查涵盖 ovenproof_scoreboard_plugin、ScoreboardAbilityCounter、ScoreboardChorus、ScoreboardDamage、ScoreboardExplosive、ScoreboardReconnect。仍需逐个及组合实测，尤其是 ovenproof 的复合行和长文本。

本版不新增“本人掉线重进”的统计恢复；ScoreboardReconnect 保持它原有的触发与恢复行为。本人不在线期间的数据不会补齐，也未增加游戏进程重启后的统计恢复。

队友重连关联依赖原 scoreboard 的 `account_id()`（缺失时回退为姓名）。如果某种会话返回重复身份或重连后身份发生变化，不能可靠归并；不会仅凭同名把不同真人强行合并。机器人沿用原统计键，不把机器人统计转移给替补真人。

运行时通过 DMF 加载钩子和局部函数包装扩展 scoreboard。行适配针对当前安装版本生成，`SOURCE_SHA256.txt` 记录源文件指纹；升级 scoreboard 后需要重新检查适配。扩展应用于三种计分板界面，不依赖 Realms 的网络 API。

## 建议测试顺序

1. 先用 1 名真人加机器人确认能加载、名字和零值正确、原插件行仍显示。
2. 8 人对局中确认八列同屏，名字不串列，基础与 ovenproof/Explosive 等插件统计对应同一玩家。
3. 把每页改为 4，翻页查看其余玩家，再改回 8；确认未丢数和未重复累计。
4. 一名队友退出、机器人补位，再由同一账号重连。确认优先级、离线标记与原记录归并。
5. 结束任务，查看结算并保存历史。重开历史确认完整名单、分页及文字/图标统计。
6. 有条件再测 9–12 人；更改分辨率或 UI 缩放后重新打开计分板，检查边界与可读性。

有问题时输入 `/rse_status`，记录版本、人数、页码、宽度；反馈发生场景、主机/客户端、分辨率、UI 缩放、启用的计分板插件及错误日志。
